# How to present information to the model: system instruction and tool results (2026-10-09)

Scope: extends `docs/llm_strengths.md` (not repeated here). Evidence strength: **C** controlled study, **B** benchmark,
**V** vendor guidance, **A** practitioner blog. "Verified" = number read on the source page (abstract, HTML or vendor
doc), not in a third-party summary. Checked against `agent/prompts/swe.md` and `step.py` (`_window`, `_task_view`,
`_context_view`, `_candidates_view`, `_finish_view`).

## 1. Structure and delimiters

| # | Claim (number) | Source | Str. | Application |
|---|---|---|---|---|
| 1.1 | Same content in plain text / Markdown / JSON / YAML: GPT-3.5 varies **up to 40%** (code translation); **no universally best format**, and the best format does not transfer between model families (IoU across series often < 0.2). GPT-4 is more robust. One case: GPT-4-32k HumanEval 76.2% plain vs **21.95%** JSON. | [arXiv 2411.10541](https://arxiv.org/html/2411.10541v1) (verified) | C | The format of the window is a variable worth measuring on the 31B, not a style choice. Do not wrap the window or the code in JSON. |
| 1.2 | Spurious format changes (separators, casing, spacing) change accuracy by **up to 76 points** (LLaMA-2-13B); the sensitivity "remains even when increasing model size, the number of few-shot examples, or performing instruction tuning". | [Sclar et al., arXiv 2310.11324](https://arxiv.org/abs/2310.11324) (verified) | C | Freeze the window layout once it works; change one thing at a time and re-run the local loop. Avoid incidental layout changes in commits that are "about" something else. |
| 1.3 | Larger models are more robust to prompt variation; **few-shot examples reduce the sensitivity**; higher decoding confidence ↔ more robustness. | [ProSA, arXiv 2410.12405](https://arxiv.org/abs/2410.12405) (verified, abstract) | C | A 31B QAT model sits in the sensitive range: a filled example (the NEXT line) at the point of use is the cheapest stabiliser. Already done. |
| 1.4 | Anthropic: wrap each kind of content (instructions, context, input) in its own XML tag to avoid misreading. OpenAI GPT-4.1: Markdown headers for sections; XML for documents; for many documents XML and `ID: 1 \| TITLE: … \| CONTENT: …` did well, "JSON performed particularly poorly". Gemini 3: XML **or** Markdown, but "choose one format and use it consistently within a single prompt". Anthropic context engineering: "the exact formatting … is likely becoming less important as models become more capable". | [Anthropic best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [GPT-4.1 guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide), [Gemini strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies), [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (all verified) | V | **Change:** `swe.md` ends with `## The issue statement` + raw `{problem_description}`. An issue that contains its own `##` headings, code fences or "Steps:" lists merges with our sections. Wrap it: `<issue>`…`</issue>`. In the window, the statement's sentences, its example and the existing test are quoted data mixed with script text: put each under a fixed label and indent (already partly done) or tag them, so the model can tell "what the statement says" from "what the script says". |
| 1.5 | Cursor (GPT-5): "structured XML specs like `<[instruction]_spec>` improved instruction adherence". | [GPT-5 guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5_prompting_guide) (verified) | A/V | Weak; no change beyond 1.4. |
| 1.6 | Gemma 4 docs give no guidance on prompt structure or few-shot; the only format rules are the turn/tool tokens and `<\|"\|>` strings. | [Gemma 4 formatting](https://ai.google.dev/gemma/docs/core/prompt-formatting-gemma4), [model card](https://huggingface.co/google/gemma-4-31B-it) (verified) | V | Nothing Gemma-specific to follow; use Gemini guidance as the closest family advice, and measure. |

## 2. Ordering

| # | Claim (number) | Source | Str. | Application |
|---|---|---|---|---|
| 2.1 | Anthropic: long data at the top, query at the end; "queries at the end can improve response quality by up to 30 percent in tests". Gemini 3: "supply all the context first. Place your specific instructions or questions at the very end", bridged with "Based on the information above…". | Anthropic best practices; Gemini strategies (verified; Anthropic's 30% is an internal test, no details) | V | System prompt: statement is last, then "Your first call is step 1": **already done**. Window: code → context → what to do → answer forms → NEXT: **already done**. |
| 2.2 | OpenAI GPT-4.1: instructions "at both the beginning and end of the provided context"; if only once, **above** works better than below. Conflicting instructions: GPT-4.1 "tends to follow the one closer to the end". | GPT-4.1 guide (verified) | V | The vendors disagree on "once"; both agree on "both ends". **Change:** add one goal line at the top of each window ("Decide: does `X` need a change for: <first requirement>?") in addition to B7's line before NEXT. Because the end wins conflicts, the NEXT line must never contradict the body (B12). |
| 2.3 | Distractors: across **18 models**, one relevant-looking distractor lowers accuracy and four lower it more; focused ~300-token prompts beat the full ~113k history (LongMemEval); shuffled haystacks beat logically ordered ones in all 18. | [Chroma Context Rot](https://www.trychroma.com/research/context-rot) (verified on the page; exact per-model numbers not read) | B | The window's "Code that X uses", callers and the test are deliberate (they removed questions), but each is a potential near-miss distractor. **Change to measure:** show a use/caller only if it shares a name with the place's changed lines or the requirements; keep the caps (8 uses, 2,500 chars, 4 callers). |
| 2.4 | Multi-turn: average **39%** drop vs single-turn over 200k+ simulated conversations; mostly unreliability; models assume early and "do not recover". Instruction drift appears **within 8 rounds** (LLaMA2-70B-chat, GPT-3.5), attributed to attention decay. | [Laban et al., arXiv 2505.06120](https://arxiv.org/abs/2505.06120); [Li et al., arXiv 2402.10962](https://arxiv.org/abs/2402.10962) (verified, abstracts) | C | Supports giving the whole task up front (statement in the system instruction: **done**) and re-stating the goal in every step (**done**). Also supports "back" being a fresh view, not a continuation of the wrong path. |

## 3. Instruction style

| # | Claim | Source | Str. | Application |
|---|---|---|---|---|
| 3.1 | Say what to do instead of what not to do (Anthropic). Gemini 3 "may overreact to open-ended system instructions such as `do not infer` or `do not guess`" (Vertex guide, German edition, verified). Negated prompts show **inverse scaling** in 9 tasks, 125M–175B (Jang et al.). | [Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices); [Vertex Gemini 3 guide (de)](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/gemini-3-prompting-guide?hl=de); [arXiv 2209.12711](https://arxiv.org/abs/2209.12711) | V; C (old models, no numbers in abstract) | `swe.md` Rules: "Change only what the requirements need; **never remove behaviour** the statement does not ask to remove" is an open-ended restriction, and our main failure is *incomplete* repair (V6, 4–14 lines vs 34–654). **Change:** "Make every change the requirements need, at every place they need it; keep the behaviour the statement does not mention, because the hidden tests also run the existing tests." Same for "Questions are not answered in this step" → "Decide from the code shown: it holds what the step needs." |
| 3.2 | Give the reason behind a rule: Anthropic's example "never use ellipses" → "…read aloud by a text-to-speech engine, so never use ellipses". | Anthropic (verified) | V | Two rules have reasons (tests: "the hidden tests replace them"). Add them for "args hold only the decision" (*the script reads each arg literally as a name, a number or code*) and "keep exact names" (*the hidden tests call those names*). |
| 3.3 | Caps and pressure: OpenAI: all-caps "generally not necessary" and existing ones may make the model follow "too strictly"; Anthropic: "CRITICAL: You MUST" causes overtriggering on newer models; Gemini 3: "avoid unnecessary or overly persuasive language"; Cursor/GPT-5: "Be THOROUGH" made the model "call search repetitively". | GPT-4.1, Anthropic, Gemini, GPT-5 guides (verified) | V | Prompt: no caps (**done**). Script answers use caps verdicts (`NOT changed`, `NOTHING changed shares its words`, `TIME IS UP`). A caps "NOTHING" in a finish view is a pressure signal that may drive a "back" loop on a covered requirement whose words differ. Keep caps for one status word at most, and say it in plain case with the reason. |
| 3.4 | Contradictory or vague instructions are "more damaging to GPT-5 than to other models": it "expends reasoning tokens searching for a way to reconcile" them. | GPT-5 guide (verified) | V | With `thinking_budget: 512`, a contradiction (e.g. the window text "too long to show whole: change it with line numbers" vs the prompt's whole-definition rule) can consume most of the budget. Adds evidence to B12. |
| 3.5 | Instruction count: best frontier model **68%** at 500 instructions; bias toward earlier instructions. | [IFScale](https://arxiv.org/abs/2507.11538) (verified, abstract) | B | Already B8. The prompt has 4 steps, 5 call forms, 4 rules: put the most-violated rule first (today "Think before the call" is first; V10's top failures were names and incomplete edits). |

## 4. Examples

| # | Claim (number) | Source | Str. | Application |
|---|---|---|---|---|
| 4.1 | Few-shot for tool use helps smaller models a lot: Claude 3 Haiku **11% → 75%** (multi-step tools, 3 examples as messages); Claude 3 Sonnet **16% → 52%** (3 semantically similar examples); examples as **messages** beat examples as strings in the system prompt; 3 ≈ 9 examples. OpenAI models gained little. | [LangChain](https://www.langchain.com/blog/few-shot-prompting-to-improve-tool-calling-performance) (verified) | B (vendor-run, small sets) | The closest thing to "examples as messages" for us is the NEXT line: a filled call in the latest tool result. **Already done.** Making NEXT fully filled (no `<placeholder>` where the script knows the value) is the high-value part. |
| 4.2 | Reasoning models: DeepSeek-R1 "Few-shot prompting consistently degrades its performance"; recommends zero-shot with the output format specified. Gemini: "always include few-shot examples", but "too many examples" overfit; keep their format consistent. Anthropic: 3–5 diverse examples in `<example>` tags; "multishot examples work with thinking" as *problem, method, answer*. | [DeepSeek-R1, arXiv 2501.12948](https://arxiv.org/html/2501.12948v1); Gemini strategies; Anthropic (verified) | C (R1 own report) / V | Conflicting. For Gemma 4 with thinking, keep **call-form** examples (format) and avoid **content** examples (a sample fix) in the system prompt, because content is copied (Agent Skills Can Be Harmful, already in CLAUDE.md). |
| 4.3 | Domain reasoning examples matter more than the reasoning channel: τ-bench airline pass^1 0.332 baseline, 0.404 think tool, **0.584** think tool + prompt with two worked reasoning examples (Claude 3.7). | [Anthropic think tool](https://www.anthropic.com/engineering/claude-think-tool) (verified; the prose says 0.370/0.570, the table 0.332/0.584) | B (vendor) | **Measure:** one short worked edit decision in `swe.md` (a fictional repo: "the window shows X; requirement says Y; line N does Z; so rewrite `f` whole with …") vs none. Risk: literal copying; use names that cannot occur in the tasks. |
| 4.4 | Placeholder style: the prompt shows 5 call forms with `<statement>`, `<candidate name>` placeholders inside raw `<\|tool_call>` syntax. GPT-4.1: important behaviour shown in examples should also be stated in rules. | GPT-4.1 guide (V); our V1/V5/V6 invented names (O) | V/O | Already says "placeholders; write the real ones". No source measured placeholder copying; keep, and watch traces for literal `<…>` args. |
| 4.5 | "Don't few-shot yourself into a rut": uniform action–observation pairs make the agent copy the pattern; Manus adds "different serialization templates, alternate phrasing, minor noise". | [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) (verified) | A | Our windows are identical in layout for every place. Watch for chains of identical decisions (`skip`, `skip`, `skip`, or the same edit form). Do **not** add random noise (1.2 says format changes cost accuracy on small models); instead make the place-specific part (head, goal line) differ visibly. |

## 6. Thinking

| # | Claim (number) | Source | Str. | Application |
|---|---|---|---|---|
| 6.1 | For thinking models: "Prefer general instructions over prescriptive steps" (Anthropic); "generally not necessary" to ask for reasoning in the output (Gemini). Structured CoT (sequence/branch/loop) beat CoT by up to **13.79%** Pass@1 on HumanEval/MBPP for ChatGPT/Codex (non-thinking). | 6.2 | Passing back earlier reasoning: Tau-Bench Retail **73.9% → 78.2%** with `previous_response_id` (GPT-5). Gemma 4: keep thoughts between tool calls in one turn; strip them before a new user turn. | GPT-5 guide; Gemma 4 docs (verified) | V | `include_thoughts: true`: **done**. Harness nudges are new user turns: thoughts before a nudge are dropped by the template; nothing to change. |

## 7. Restating the task in long loops

| # | Claim (number) | Source | Str. | Application |
|---|---|---|---|---|
| 7.1 | Prompt repetition: **47 of 70** wins, **0 losses** without reasoning; with reasoning **5 wins, 1 loss, 22 neutral** (7 models incl. DeepSeek V3, Gemini Flash). | [Leviathan et al., arXiv 2512.14982](https://arxiv.org/html/2512.14982v1) (verified) | C | With thinking on, repeating the *whole* statement is not supported as an accuracy gain; its value for us is surviving compaction and lost-in-the-middle. **Change to measure:** in windows 2…N repeat requirements + example, and only the statement sentences that name the place (the full statement is never compacted in the system instruction). Saves tokens before the 14,336 compaction. |
| 7.2 | Re-reading the question (RE2) helps reasoning in 112 experiments on 14 datasets, except a few with vanilla ChatGPT. | [arXiv 2309.06275](https://arxiv.org/html/2309.06275v3) (summary only, numbers not read) | C | Same as 7.1. |
| 7.3 | Recitation: Manus rewrites `todo.md`, "reciting its objectives into the end of the context" (~50 tool calls per task). Anthropic: structured note-taking / to-do lists; JSON for structured state, free text for progress. | Manus; Context engineering; Anthropic best practices (verified) | A/V | **Change:** before NEXT, a one-line plan status: "Plan: `Session.send` changed · `Session.request` now · `merge_setting` next (2 of 3)". The window head has "place i of N" but not which are done or what remains. |
| 7.4 | Keep errors in context ("Erasing failure removes evidence", Manus) vs describe-don't-quote (Feedback That Backfires, B5). | Manus (A); arXiv 2608.23651 (C) | — | Reconcile: keep a one-line *description* of a failed edit (evidence) in the next answer; never the failed text. Already B5. |
| 7.5 | Tool-result clearing is "one of the safest lightest touch forms of compaction". | Context engineering (verified) | V | The harness compacts, not us; nothing to change. Each window must stand alone (it does). |

## 8. Small and open models

- Format sensitivity is larger for smaller/older models and does not vanish with size (1.1–1.3): measure layout, freeze it.
- Few-shot helps smaller models more (4.1, ProSA); for reasoning models content examples can hurt (4.2): use filled NEXT calls, not sample fixes.
- Order and middle-of-context effects are stronger for small models (Tang et al., already B13); distractors hurt all sizes (2.3).
- Vendors now warn that emphasis and "be thorough" over-trigger *frontier* models (3.3); for a 31B the safe choice is still plain, positive, reasoned rules — no evidence that caps help small models either.
- Not found: any controlled study of XML vs Markdown for Gemma, of instruction count for 30B-class models, or of placeholder copying in tool-call examples.

## Proposed checklist items

| # | The model does well / badly | Evidence | Check question |
|---|---|---|---|
| P1 | **Badly: telling quoted data from instructions** when the issue text or test text is pasted without a boundary | Anthropic/OpenAI/Gemini delimiter guidance V; format sensitivity up to 76 pts (Sclar) C | Is every piece of quoted data (statement, example, test, code) inside a fixed label or tag that the instruction text never uses? |
| P2 | **Badly: absorbing format changes**; accuracy moves with layout, more in smaller models | arXiv 2411.10541 (40%), Sclar (76 pts), ProSA C | Does this change alter the layout of an answer the model already handles? Was the old layout kept for comparison? |
| P3 | **Well: following positive rules with a reason; badly: open-ended prohibitions** (it overreacts or under-acts) | Anthropic, Vertex Gemini 3 V; negated prompts inverse scaling C | Is every rule phrased as what to do, with the reason in the same sentence? Could a "never/only" rule make the model change too little? |
| P4 | **Badly: emphasis and pressure words** (caps, MUST, NOTHING) make it overreact | OpenAI, Anthropic, Gemini, Cursor/GPT-5 V | Does any answer use caps or pressure words? Would plain wording plus a reason do? |
| P5 | **Badly: spending a small thinking budget on contradictions** | GPT-5 guide V; GPT-4.1 "later instruction wins" V | With 512 thinking tokens, can the model act on this answer without reconciling two statements? |
| P6 | **Well: using a goal stated at both ends** of a long answer | Liu et al. C; GPT-4.1, Anthropic (30%), Gemini V | Is the decision question in the first line and again just before NEXT? |
| P7 | **Badly: ignoring relevant-looking but unneeded context** (near-miss distractors) | Chroma, 18 models B | Does every block of context in the answer bear on the decision of this step? Could it be shorter? |
| P8 | **Well: keeping track when progress is recited** (to-do status at the end) | Manus A; Anthropic note-taking V; instruction drift in 8 rounds C | Does each answer end with what is done, what is now, and what remains? |
| P9 | **Badly: copying content examples; well: copying call-form examples** | DeepSeek-R1 C; LangChain 11→75% B; Agent Skills Can Be Harmful C | Is every example in the prompt a call form or a filled NEXT, never a sample fix that could be taken as the requirement? |
| P10 | **Badly: uniform repeated observations** lead it to repeat its last decision | Manus A; self-conditioning (B5) C | In a run of windows, does the place-specific part (head, goal) differ visibly? Do traces show chains of identical decisions? |
