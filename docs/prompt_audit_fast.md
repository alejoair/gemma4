# Audit of every prompt and answer of the fast build (10-17, on the vf3 traces)

The user asked for this audit on 10-17 ("Revisa todos los prompts y feedback que da el sistema"). Four reviewers read
every text the model reads in the fast build:
- the instructions generated by `tools/make_fast.py`;
- the harness task message;
- every answer of `_stages.py` and `step.py`.

They checked each against `docs/llm_checklist.md` and the 30 vf3 traces from the Kaggle eval with Gemma. The findings
are below by agent, with the trace that shows each one. The fixes went into vf5; the checklist table is in
`docs/design_fast.md` ("vf5").

## Requirements, task message, finish

| # | Severity | Finding | Fix in vf5 |
|---|---|---|---|
| 1 | high | `req.py` read a call by its position: after one names lookup, any call was saved. Two or more short names became R1. | Decided by content: pairs that look like requirements are saved; short names, at most 4 words each, no commands, fewer than 3 lookups, are a names lookup. |
| 2 | high | The "already finished" answer was garbled ("Saved 1 requirements:."). It hid what was saved and did not say a resend replaces it. | The answer lists R1.. and says that sending the pairs again replaces them until the locate agents start. |

The agent hunted for tools (grep, `load_skill_resource`). | The top of the instruction says the task message is for the whole team; this agent reads no files and runs no commands, with the reason. |
| 4 | medium | A file path or module name was answered as "a parameter, attribute or variable". | Answered "the module <path>; it defines ...", listing its definitions and up to 6 top-level assignments. |
| 5 | medium | Step 3 gave no fact when the saved requirements were wrong. | The instruction and the answer say that sending the pairs again replaces them. |
| 6 | medium | vf4's refusal of a single code name talked about commands. | A single name is a names lookup; the command refusal is used only for commands. |
| 7 | medium | Finish said the patch was ready, but 2 of 8 patches were empty with 2.5 minutes left. | Repair retries once, on the main place, when the diff is empty and time is left. |
