# What each script must do, the literature behind it, and the review of 2026-10-09

The agent has one entry point, `agent/skills/swe/scripts/step.py`; the other modules are internal. Each row is a
requirement. **Status** comes from reading the code (2026-10-09 review); only a run against the model, monitored
through the gateway, counts as evidence that it works. **Literature** gives the papers that use a similar technique,
the number that supports it, and where ours differs or what the papers show we lack (**gap**).

The papers were read on 2026-10-09 (PDFs and text in the session scratchpad, `papers/`). The numbers are from their
tables. Localization numbers are not comparable with ours: other benchmarks, and the metrics differ ("all gold in
top k" in LocAgent and SweRank, "any gold" in BLAgent and in our 76%).

## step.py: one call per decision; the answer ends with the exact next call (NEXT line)

## What the literature says about the design as a whole

- **For the fixed, enforced procedure with open models:**
  - SWE-Gym: the Moatless workflow 19% vs OpenHands 3% zero-shot at 32B.
  - Harness study: planning helps weaker models most; typed tools with lint 25.2 vs bash 10.2.
  - StateFlow, SOP-Agent and Blueprint First: enforcement beats instructions.
  - SWE-Search: loosening the procedure adds loops.
- **What a fixed procedure must still offer:** viewing, search and execution (SWE-agent, AutoCodeRover); impact after each edit (CodePlan); a verdict that can say "not verified" when no test covers the change (SWE-ABS, PatchDiff).
- **Gaps that fit the design (all inside `step.py`):**
  - contiguous 100-line views;
  - text search;
  - a before/after view on a rejected edit;
  - a budget-aware final NEXT;
  - test selection by execution plus a coverage-gap NOT VERIFIED;
  - a measured AssertFlip-style fail-to-pass check;
  - impact recomputed after an edit by change type;
  - one demonstration in the prompt.
